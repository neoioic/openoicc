# 原 oicc 功能核对

2026-10-18：按帮助命令、节点注释标记和宿主创建函数三个入口核对。OpenOICC 面向 [NEOioic](https://github.com/neoioic/neoioic)，使用当前 API 名称；对照目标是用户操作与生成职责。

## 功能与证据

经本次任务授权，只读检查上游资料，将原 Windows oicc 1.0.18 复制到本仓库忽略的构建目录后执行。`-h`、`-help` 确认类型为不区分大小写的 `go/ao/co/ro/mo`，目录默认当前目录；无类型参数时检查宿主目录、写入所需 CRT 并清空多余 CRT。实际执行分类创建，核对宿主、Main 入口、go/ao 子节点、保留名称和重复名称处理。OpenOICC 现已提供这些操作，另保留单文件 `new`、显式文件 `check/generate` 和成功返回 0 的 CLI 约定。

节点 `<ibn>` 决定有序继承，`<crt>` 是唯一替换范围。宿主创建分支是用户代码：历史教程明确要求手工声明并调用构造器，仅作为基节点使用的节点不需要独立构造器。旧 `__CreateObject__` 对应当前 `host_create_object`；目录模式从该函数内的直接 `crt_name(...)` 调用选择目标，不生成或重写 switch。移除某个调用后，相应节点构造区会清空，业务代码保留。

OpenOICC 的分类模板使用当前九接口与头文件链，只保留有用途的分组头文件，不复制旧工具的空分组 `.c` 和历史注释。模型编号、宿主编号和业务创建分支由用户填写。生成宿主管理 OID 分配回收，拒绝销毁仍打开的对象，区分动态与外部存储所有权。

## 安全契约的取舍

以下差异均由任务所附安全报告覆盖，按用户指示采用 NEOioic 的修复契约。运行时修复保存在固定依赖中，生成器与宿主模板遵守它们，不恢复旧行为。

| 安全报告条目 | 当前采用的契约 |
| --- | --- |
| 1、2 | 空队列头尾 NULL；合法环形指针运算；容量零禁用；调整容量失败保持原队列 |
| 3、4 | 流尺寸在运行时检查，以 memcpy 读写本机整数，不依赖对齐或 Release assert |
| 5、6 | SBO 接力单继承传递结果，多继承返回专用中性值 |
| 7 | 部分关闭返回 RN_CLOSEPARTIAL，只允许继续清理，不能伪装成仍完整打开 |
| 8 | size_t 布局与溢出检查；按席位倍数限制 caller_capacity，拒绝字段窄化 |
| 9 | 外部构造区清零；容量、对齐及有效期仍由调用者保证 |
| 10 | 根节点打开/关闭保护引用计数上下界 |
| 11 | OID 耗尽受控失败，外部存储清理不解引用 NULL object_out，不释放调用者本体 |

成员块对齐沿用当前 NEOioic 的 `NEOIOIC_ALIGNED_SIZE`；超过当前布局对齐能力的成员明确拒绝。没有修改固定运行时或添加旧接口别名。本轮未确认到需要另行决策的、上述安全修复之外的对象模型契约冲突；后续若发现则先报告。

## 验证与限制

常规回归不依赖原程序：在临时副本中执行目录构造，将参考示例更新前后的 11 项业务输出对照；检查未选中的基节点构造区清空、重复运行稳定、错误不写入，以及新宿主动态/外部存储、OID 耗尽和回收。工具分配故障注入覆盖显式生成、单文件创建、目录构造和分类创建。

本机原程序的目录构造报 `E0018: can't open strm_nodestru file`，在其自身创建的骨架上也如此，因此未获得成功的原二进制构造输出作为差分基线。现有证据来自其帮助、实际创建结果、教程、运行时及参考构造器；不能宣称已对原生成算法的全部输入完成等价验证。当前解析语法与委托容量边界见 [生成契约](openoicc.md)。
