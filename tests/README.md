# OpenOICC 回归验证

运行方式与平台记录见 [构建说明](../docs/build.md)。测试使用 Python 标准库和 PATH 中的 C11 编译器，默认 GCC，`--cc clang` 可选择 Clang（也可传编译器可执行文件路径）；该选择用于全部测试编译，包括编译失败检查和自举。产物全部位于 `build/tests/` 下独占临时目录。测试源码统一使用 LF；CRLF、非法 UTF-8、NUL 等样例以字节或转义字符串动态构造。

测试方法数量不是覆盖率，也不能证明不存在缺陷。当前 36 个测试方法包含以下边界矩阵与运行检查：

- 每个截断字节前缀、18 种非法 UTF-8 和 8 种合法编码边界；非法编码同时验证源文件和成员头文件。
- 六种标记逐个删除/复制、35 次固定种子的标记乱序、80 份固定种子的任意字节输入；失败不得覆盖原文件或留下临时文件。
- 构造区文件作用域、花括号不配对、宏伪绑定、错误返回类型、重复绑定、成员与头文件守卫歧义、大小写根名称冲突。
- 8192 字节读取块附近、16 KiB 边界、1 MiB 文件；BOM、空白行、无末尾换行、只读目标、临时文件重名及不覆盖创建。
- 120 层链、96 分支共享根、固定随机继承图；另有 3 个随机种子各生成 12 个节点，编译后按独立 Python 模型逐项检查节点、直接基节点、祖先顺序、席位和打开/关闭行为。
- `construct.c` 对 22 种无效布局分别测试动态和外部存储模式；覆盖模型/数量字段、索引、NULL 参数、席位、对齐、尺寸溢出、OID 最后有效块与越界。拒绝布局不分配内存、不消耗 OID、不写外部存储。
- 生成代码的模型编号编译期边界、过度对齐成员运行期拒绝；`new` 产出的九接口骨架实际编译、创建、打开、交互和关闭。
- 为多文件继承项目（含成员头文件）及 `new` 的每个成功路径分配点注入一次失败，核对退出状态、资源计数、原文件与临时文件。多文件路径覆盖已准备前一个文件后才失败的情况。
- 原参考构造器业务输出对照、菱形共享、嵌套委托席位峰值、分配失败、部分关闭重试、OID 回收及自举重编译等既有回归。

`alloc.c` 追踪生成构造器的分配；`tool_alloc.c` 在测试编译时替换工具的分配函数。生产程序不包含故障注入开关。`files.c` 只操作测试进程的当前临时目录，不修改系统权限或全局配置。

第三方材料仍有用途：`third_party/oioic` 是生产依赖；`examples/oioic_reference` 是构造生成前后行为比较的基线；许可与 `SOURCE.json` 是分发和来源记录；参考文档解释对象模型与生成契约。这些材料没有因工具初版完成而失效，不能作为无用文件移除。
